# 구조와 유지보수

서버는 실제 봇 제어 호출에서 식별한 컨텍스트와 소유자, 현재 플레이어 명단, 이름, 연결 쿠키 및 ID를 재검증합니다. 이름이나 전역 AI 플래그만으로 봇을 추정하지 않습니다. 요청 시 팀·대상·좌석을 다시 확인하고 원래 엔진의 진입/하차 경로를 사용합니다.

배치 화면에서는 서버가 선택한 실제 장비와 봇 운전석을 검증해 짧은 유효 기간의 공유 메모리 증명을 발행합니다. 클라이언트는 로컬 플레이어와 실제 선택 장비·운전자의 ID 및 팀이 맞을 때만 배치 가능 상태를 임시 허용합니다. 여러 UI 작업 스레드가 겹쳐 실행돼도 마지막 호출이 끝날 때 원래 상태로 복원합니다.

만석 예외는 클라이언트 RVA 4064f1의 원래 FULL 계산 직후에 적용합니다. 원래 CALL 다음의 직선 코드 6바이트만 이전하며, 투명 MASM 연결부가 하드웨어 상태를 보존합니다. 실제 탑승자 수나 MaxPlayers 값을 바꾸지 않고 이후 원래 상태 검사를 실행합니다. 상세 ABI와 한계는 native-client/abi/README.md에 있습니다.

원래 함수 호출 중에는 UI 공유 잠금을 유지하지 않습니다. 비활성화 시 훅을 끄고 활성 카운터·다른 스레드의 모듈/트램펄린 실행 위치를 확인합니다. 안전한 해제를 증명하지 못하면 DLL을 로드된 비활성 상태로 남깁니다. 실행 파일 해시와 대상 명령 바이트가 다르면 적용을 거부합니다.

native-adapter/README.md와 core/README.md는 초기 추상 경계에 대한 설명을 포함합니다. 실제 런타임 진입점은 seat_addon.cpp와 client_addon.cpp입니다. 현재 설치/사용 안내는 저장소 루트 README를 기준으로 합니다.
